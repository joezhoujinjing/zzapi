# enterprise risk 的 38 项覆盖范围与解读细则

SKILL.md 只讲怎么用；这里是回答时要说清的边界、每一项的解读要点和实测案例。

## 覆盖范围（12 类 38 项）

| 分类 | 项目 |
|---|---|
| 司法 (9) | 失信被执行人、股权冻结、终本案件、被执行人、失信被执行人（司法公示）、限制高消费、破产重整、司法拍卖、询价评估 |
| 采购 (4) | 央企供应商不良行为、政府采购违法失信、军队采购失信、军队暂停资格 |
| 工商 (5) | 严重违法失信企业、空壳公司、假冒国企、经营异常名录、严重违法（工商公示） |
| 税务 (4) | 重大税收违法失信、非正常户、重大税收违法（工商公示）、欠税公告 |
| 安全 (2) | 事故责任企业名录、安全生产严重失信 |
| 医药 (3) | 价格招采失信医药企业、药品联采违规名单、欺诈骗保 |
| 劳动 (1) | 拖欠农民工工资 |
| 制裁 (1) | 制裁与反制裁清单 |
| 组织 (1) | 涉嫌非法社会组织 |
| 处罚 (3) | 行政处罚、环保处罚、违法建设 |
| 担保 (3) | 股权出质、知识产权出质、动产抵押 |
| 存续 (2) | 注销公告、清算组备案 |

**不包含**（有意的）：开庭公告 / 立案 / 裁判文书 / 法院公告。实测 8 家样本合计
646 / 473 / 339 / 53 条，家家都有、动辄上百，是常态数据不是风险命中；塞进
「只列命中」的扇出会把真信号淹没。而且它们带角色字段（原告/被告/申请人），
**当原告不是风险**，简单计数会把主动维权的公司误判成高风险。要看明细走
`zzapi judicial hearing|case|judgment|notice <企业>`（默认字段带 role，`meta.totalCount` 给条数）。

## 命中不等于这家企业有问题——先看主体

担保/司法类记录必须先看主体是谁，否则会把别人的事算到这家头上。命中项带 `note` 提示：

| 项目 | 要看的字段 |
|---|---|
| 股权出质 | `pledgor` 出质方 / `pawnee` 质权人。本企业是 `pawnee` 则它是**债权人**，不是风险 |
| 知识产权出质 | `pledgor` 是出质方。本企业若为 pledgor，说明以知识产权质押融资 |
| 动产抵押 | `mortgagees` 是抵押权人（债权方） |
| 股权冻结 | `beExecutedPerson` 可能是**母公司**而非本企业 |
| 终本案件 / 被执行人 | `name` 可能是关联公司；被执行 ≠ 失信，有执行案件不等于拒不履行 |
| 限制高消费 | `name` 是被限制的自然人（通常是法定代表人），`companyName` 是其关联企业 |
| 破产重整 | `name` 是被申请人；本企业也可能是申请人。命中且为被申请人，准入通常硬否决 |
| 司法拍卖 | 看 `role`——本企业可能是拍品所有人（资产被处置），也可能只是关联方 |

还要看 `status` / `cancelDate` / `loseEfficacyDate`——很多记录**早已解除或失效**。
实测例：某钢企「股权冻结 2 条」，主体是母公司、且 2007 年就已解除。

**注销公告 / 清算组备案命中是硬否决项**——企业正在走解散流程，即使工商状态仍显示
「存续」。实测例：一家陶瓷企业状态「存续」，但 2025-10-11 已决议解散、债权人公告期已过。

## 三对可能重复计数

同一事项的两条数据管线，可能同时命中同一件事，统计条数时别重复计：

- `严重违法（工商公示）` ↔ `严重违法失信企业`
- `重大税收违法（工商公示）` ↔ `重大税收违法失信`
- `失信被执行人（司法公示）` ↔ `失信被执行人`（前者带标的金额与履行情况）

## 命中之后要接着看的

- **是否仍在效期内**：`jchmd`（解除黑名单时间）可能是具体日期、`永久`、或 `-`。
  例：北信源被中海油禁用至 2026-11-11，被大唐永久禁用——前者会过期，后者不会
- **处罚是否穿透到人**：军队采购失信可能写明「法定代表人控股或管理的其他企业
  一并禁止」。这时**只查这一个信用代码是不够的**，用 `zzapi relation child|graph <企业>`
  找关联企业再查
- **历史口径**：`--history` 切到历史口径（22 项支持）。很多记录只存在于历史侧——
  实测某钢企当前口径 2 项命中，加 `--history` 变 4 项（多出欠税、终本案件、股权出质）。
  做尽调时两个口径都要跑

## 已知的平台侧情况

- **平台数据会变。** 实测某企业的央企供应商黑名单记录在一天之内从「2 条」变为
  「0 条」——接口正常、是平台侧数据被清理。结论要表述为「截至查询时」，重要判断
  建议留存查询时间与原始输出
- **行政处罚 v2 接口尚未开通**（平台报 `API_NOT_PROVISIONED`），「处罚 → 行政处罚」
  走的是另一条可用管线，功能不受影响
- **调用频次按接口独立计**：每家企业一次体检打 41 次接口（1 次归一化 + 38 项 + 2 项背景），
  家数多时容易触发 `RATE_LIMITED`(8)。用 `--only` 缩小范围、等一会儿重试
