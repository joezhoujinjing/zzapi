# 供应商风险查询

命令行工具 `zzapi` 已全局安装，凭证走 `ZZAPI_APP_KEY` / `ZZAPI_APP_SECRET`。

## 两步：先定位企业，再体检

```bash
zzapi enterprise search 北信源          # 模糊搜，拿统一社会信用代码
zzapi enterprise risk 91110000101967333M   # 17 项并发体检
```

`risk` 也直接收**精确全名**（内部自动换成代码）：`zzapi enterprise risk 北京北信源软件股份有限公司`。
但**模糊名不行**，会报 `ENTERPRISE_NOT_FOUND`（exit 4）——那时回到 `search`。

### 有歧义就先问用户，不要自己挑

搜索是模糊匹配，会串进无关企业：搜「中富通」命中「晋中富通建材经销部」，
搜「北信源」命中「河北信源纺织」。而**同名不同企业的风险可能完全相反**：

```
湘潭钢铁集团有限公司      → 国家电网黑名单
湖南华菱湘潭钢铁有限公司   → 17 项全清
```

所以 `search` 返回多条时，**先把候选列给用户确认，再查 risk**。别自己挑第一条——
排序不代表相关度，挑错了会给出一份张冠李戴的风险结论，比查不到更糟。

列候选时带上能帮人分辨的信息：企业全名、信用代码、行业、注册资本、成立日期。

```bash
zzapi enterprise search 金狮王陶瓷
#  广东金狮王陶瓷科技有限公司   91440604MA536WUD6K  软件和信息技术服务业  600万  2019-04-29
#  淄博金狮王陶瓷文化发展有限公司 91370302MA3CD8X65E  文化活动服务        600万  2016-07-05
# → 两家都在，法人还是同一个人。问用户要查哪家，或者两家一起查。
```

只有一条命中（`totalCount: 1`）时才可以直接往下走。

## 怎么读体检结果

**默认只列命中项**。空输出 = 干净，**不是查询失败**。判断依据看 `meta`：

```json
{"items":[], "count":0,
 "meta":{"companyName":"...","socialCreditCode":"...",
         "shellRiskScore":17.83,"shellRiskLevel":"低风险",
         "relatedDishonestCount":4,"relatedExecutedCount":1,
         "checked":38,"hit":0,"clean":31,"failed":0,"hitCategories":[]}}
```

- `failed > 0` 才是真出问题，那几项没查成
- 想确认 38 项都实打实跑过，用 `--all`，它会把「无记录」的项也列出来

**`relatedDishonestCount` / `relatedExecutedCount` 是关联方的失信/被执行数**——
不是本企业的记录，38 项里一条都看不到。「本企业干净但关联着 4 家失信企业」
是准入判断的关键信息，必须一并报告。

**`shellRiskScore` 是平台算的空壳指数，不是事实记录**，所以放在 meta 而不是命中项里。
实测量表：`<20` 低风险 · `20–40` 中低 · `40+` 中风险。引用时要说明这是平台评分，
和「某机关某日登记了某事」性质不同。

### 命中不等于这家企业有问题

新增的担保/司法类记录**必须先看主体是谁**，否则会把别人的事算到这家头上。
命中项会带 `note` 字段直接提示，务必照做：

| 接口 | 要看的字段 |
|---|---|
| 股权出质 | `pledgor` 出质方 / `pawnee` 质权人。本企业是 `pawnee` 则它是**债权人**，不是风险 |
| 动产抵押 | `mortgagees` 是抵押权人（债权方） |
| 股权冻结 | `beExecutedPerson` 可能是**母公司**而非本企业 |
| 终本案件 | `name` 可能是关联公司 |

还要看 `status` / `cancelDate` / `loseEfficacyDate`——很多记录**早已解除或失效**。
实测例：某钢企「股权冻结 2 条」，主体是母公司、且 2007 年就已解除。

**注销公告 / 清算组备案命中是硬否决项**——企业正在走解散流程，即使工商状态仍显示
「存续」。实测例：一家陶瓷企业状态「存续」，但 2025-10-11 已决议解散、债权人公告
期已过。

### 两对可能重复计数

`严重违法（工商公示）` 与 `严重违法失信企业`、`重大税收违法（工商公示）` 与
`重大税收违法失信` 各是同一事项的两条数据管线，可能同时命中同一件事。
统计条数时注意别重复计。

## 命中之后要接着看的

- **是否仍在效期内**：`jchmd`（解除黑名单时间）可能是具体日期、`永久`、或 `-`。
  例：北信源被中海油禁用至 2026-11-11，被大唐永久禁用——前者会过期，后者不会
- **处罚是否穿透到人**：军队采购失信可能写明「法定代表人控股或管理的其他企业
  一并禁止」。这时**只查这一个信用代码是不够的**，需要另查关联企业

## 常用参数

```bash
zzapi enterprise risk <x> --only 采购,司法    # 只查某几类
zzapi enterprise risk <x> --all              # 含未命中项，用于自证查全了
zzapi enterprise risk <x> --history          # 历史口径（7 个接口支持）
zzapi enterprise risk <x> --full             # 无损，输出接口全部原始字段
zzapi enterprise risk <a>,<b>                # 一次多家（最多 10）
```

十二个分类：`司法`(9) `采购`(4) `工商`(5) `税务`(4) `安全`(2) `医药`(3) `劳动`(1)
`制裁`(1) `组织`(1) `处罚`(3) `担保`(3) `存续`(2)，共 38 项。

`--history` 切到历史口径。**很多记录只存在于历史侧**——实测某钢企当前口径 2 项命中，
加 `--history` 变 4 项（多出欠税、终本案件、股权出质）。做尽调时两个口径都要跑。

**一条命令最多 10 家企业**，超了报 `TOO_MANY_ENTITIES`（exit 2）。
每家会打 17 次接口，家数多时容易触发平台频次限制，可用 `--only` 缩小范围。

## 覆盖范围——回答时必须说清的边界

| 分类 | 项目 |
|---|---|
| 司法 | 失信被执行人、股权冻结、终本案件、被执行人、执行案件、限制高消费、破产重整、司法拍卖、询价评估 |
| 采购 | 央企供应商不良行为、政府采购违法失信、军队采购失信、军队暂停资格 |
| 工商 | 严重违法失信企业、空壳公司、假冒国企、经营异常名录、严重违法（工商公示） |
| 税务 | 重大税收违法失信、非正常户、重大税收违法（工商公示）、欠税公告 |
| 安全 | 事故责任企业名录、安全生产严重失信 |
| 医药 | 价格招采失信医药企业、药品联采违规名单、欺诈骗保 |
| 劳动 | 拖欠农民工工资 |
| 制裁 | 制裁与反制裁清单 |
| 组织 | 涉嫌非法社会组织 |
| 处罚 | 行政处罚、环保处罚、违法建设 |
| 担保 | 股权出质、知识产权出质、动产抵押 |
| 存续 | 注销公告、清算组备案 |

**不包含**：涉诉明细（开庭公告/案件/诉讼角色，数据量大且家家都有，不属稀疏风险
信号）、对外投资、关联企业穿透明细、知识产权持有情况。

**平台数据会变。** 实测某企业的央企供应商黑名单记录在一天之内从「2 条」变为
「0 条」——接口正常、是平台侧数据被清理。所以结论应表述为「截至查询时」，
重要判断建议留存查询时间与原始输出。

全清的正确说法是「**在这 38 项中没有记录**」，而不是「这家公司没有风险」。

**行政处罚 v2 接口尚未开通**（平台报 `API_NOT_PROVISIONED`），但上表的「处罚 → 行政处罚」
走的是另一条可用管线，功能不受影响。

**处罚可能穿透到自然人**：军队采购失信曾出现「法定代表人控股或管理的其他企业一并
禁止」。这时只查这一个信用代码不够，需另查关联企业（平台的关联企业接口尚未接入）。

## 报错

`ENTERPRISE_NOT_FOUND`(4) 名字不精确 → 回 `search` ·
`TOO_MANY_ENTITIES`(2) 一次超过 10 家 → 分批 ·
`RATE_LIMITED`(8) 触发频次限制 → 等一会儿重试，别急着重跑 ·
`PARTIAL`(6) 部分项失败 → 看每项 `ok`
